## 1. Source identity is not effect identity

One ArchiveId has one CaptureSessionId/ClockId. Restart creates new IDs and an archive, never a continuation of the old monotonic clock. IDs are recorded at setup, not generated by replay. An ArchiveId reused for different content is ArchiveIdentityConflict.

| Concept | Exact logical value |
|---|---|
| RecordRef / InputCursor | (ArchiveId, RecordNo); references an actual WAL record, including administrative/control inputs |
| RawFrameId | (ArchiveId, raw_record_no), where the record kind is RawInput |
| SourceCandidateKey | (RawFrameId, raw_sub_index:u32, normalizer_revision:u32) |
| SourceApplicationKey | SourceCandidateKey; used for at-most-once application, not the proof record ID |
| EventId | (ArchiveId, apply_record_no, output_index:u32, normalizer_revision:u32) |
| EventCursor | (apply_record_no, output_index), lexicographic within one ArchiveId across all recorded normalizer activations |

`cause_record_no` is an alias of **apply_record_no**, not necessarily the raw record. A raw book frame creates candidates and NO confirmed book event. A proof may enable application later, including release of an earlier blocked prefix. Each effect has a distinct immutable EventId and an explicit source key. Its availability is never rewritten from raw time to proof time.

The canonical event projection contains BookSnapshot, BookUpdate and Trade effects only. WAL control/definition/diagnostic observations use RecordRef, not invented market EventIds. A record emitting no market effect has no EventCursor. This deliberate separation removes ambiguity over a control event consuming output index 0. Consumers may expose control observations separately, but not silently add them to this projection.

At each apply step, index outputs densely from 0 in the release order in section 3. No outputs => no IDs. A frame's source sub-index and the step's output index can differ when the step releases multiple frames. Candidate index 0..count-1 is fixed by the selected content-bound normalizer/profile, not HashMap iteration. Consumer redelivery of identical EventId and canonical fields is a no-op; changed fields are IdentityConflict. A repeated RecordNo inside the WAL is RecordOrderError, not consumer redelivery.

Same archive, artifacts and recorded activation timeline reproduce the same IDs. Another capture need not. These are NOT exchange dedup keys. Alternate research normalization needs a separate research namespace and is not canonical parity.

## 2. Envelope, availability and causal basis

| Field | Requirement |
|---|---|
| schema_version | logical event schema 1 in proposal revision 2; unsupported => error; not Rust memory layout |
| event_id / available_at | EventId / exactly its EventCursor |
| source_candidate / raw_input_ref | exact SourceCandidateKey / RawFrameId |
| source_ingest_order | original raw RecordNo; distinct from apply_record_no |
| channel, stream_id, instrument, spec_version | registered StreamId and qualified SpecRef |
| connection_id, connection_epoch, subscription_epoch | owner-qualified current generations |
| book_id, book_epoch | Some for book effects, None for Trade; no borrowed epoch |
| source_timestamp | Unknown or Known(i64 value, unit, Token32 origin); Seconds=1, Millis=2, Micros=3, Nanos=4 |
| local_receive_unix_ns / local_receive_monotonic | ORIGINAL raw samples; monotonic includes recorded session/clock IDs |
| applied_at_monotonic | evaluation maximum at apply step; never substituted for the data sample |
| config_version, normalizer_revision, feed_profile_version | exact recorded active context and resolved artifacts; pending cannot survive an incompatible activation |
| as_of | CausalBasis { record_frontier: RecordNo, prior_effects: ordered unique EventCursor references } |
| record_schema_version, artifact_refs | WAL schema plus the exact resolved config/profile/proof references |

**Explicit semantic delta:** as_of is now a CausalBasis, not a fabricated EventCursor for a raw/control record. In v1, its record_frontier is conservatively the entire recorded prefix through apply_record_no. This includes the proof, evaluation-clock inputs, config, invalidations and ordering prerequisites. Optional prior_effects must exist and precede the effect lexicographically (including lower output indices of this step). Forward references fail FutureCausalReference. The proof descriptor's basis records must precede the proof itself. Prefix coverage does not imply that every earlier market event belongs to this stream.

Both availability and causal frontier can therefore advance when a delayed proof releases old raw data. Example raw10/raw11, proof11 at12, proof10 at13: release at13 has cursors (13,0),(13,1), as_of.record_frontier=13, original raw receive times unchanged. No raw reference is invented as an EventCursor.

Unknown source time is not zero or local time. Unit conversion is checked and needs known units, never guessed from digit count. Exchange timestamps, equal or missing, do not alter admission/application order. Aggressor=Unknown/Buy/Sell; RPI=Unknown/Yes/No; trade_book_link=Unknown/Proven(reference,evidence). Proximity in exchange time is not proof of linkage or aggressor. Real Bitget mappings remain BLOCKED_BY_MD_001.

## 3. A1: frame verification, ordered release and bounded pending

Book proof scope is **one complete raw frame of one StreamId, full tag, config, normalizer and feed profile**. The descriptor resolves its raw identity, invalidation barrier, source continuity basis and complete ordered output commitment ([artifacts section 4](../domain/artifacts-v1.md#4-evidence-bodies-and-scope)). Snapshot frames have exactly one BookSnapshot output. Delta frames have one or more BookUpdate outputs. Mixed snapshot/delta, book/trade or multi-stream frames are MixedFrameUnsupported in v1. No sub-event proof and no partial frame success.

At raw admission, validate definitions, current context, normalized structure and resource bounds, then append candidates to that stream's pending sequence in increasing raw RecordNo. An unverified but structurally valid frame is pending, not a validity failure. An old-tag raw is diagnostic only, never pending. A structurally invalid CURRENT book frame fails closed and sets the barrier at this record. Trade-only frames can emit Trade effects immediately after structural/profile validation; unknown aggressor/link remains unknown. Book VerificationEvidence does not confirm trades. Missing required artifacts blocks dependent canonical interpretation, not framing diagnostics.

At VerificationEvidence, first resolve and validate its complete descriptor against the referenced raw and previously recorded basis. A matching pending frame becomes proof-ready. A proof-ready later frame waits for earlier pending frames in its writer-stream. Release only the maximal ready prefix, ordered by raw RecordNo then raw_sub_index. Other streams neither wait nor release merely because this stream obtained proof. Validate each whole frame against the working anchor BEFORE applying any of its outputs. If a later released frame fails, earlier complete frames of this step remain applied and auditable; the failed frame has no partial effects and invalidates the scope at the current RecordNo. Final readiness is false and publication candidates for that scope are revoked.

Each released output gets the CURRENT apply RecordNo and dense output_index, not its proof receipt's earlier RecordNo. Thus a saved proof at12 can lead to an effect at13. Snapshot => new anchor/Warming, no progress increment. Each applied BookUpdate output contributes one unit of capped warm-up progress; levels and proof records do not count. At application, last-valid-data sample is max(previous sample, original raw sample) within the clock domain. Proof time cannot refresh stale data. The original sample is also retained per effect.

Pending bounds are required versioned config-descriptor fields: max frames, sum of raw_len bytes, sum of candidate output counts, and max wait nanoseconds. Frame count 1..256, raw bytes 1..16777216, output count 1..65536; wait>0. These are proposed engineering safety caps, not feed timings or proof of a production heap bound. Deadline=checked(raw receive sample+wait). On every valid recorded clock advance, BEFORE proof release, evaluation>=deadline invalidates that stream as PendingTimeout. Checked overflow is PendingDeadlineOverflow. A new raw exceeding any bound => PendingOverflow; do not silently evict/skip. The triggering recorded input identifies the failure even if storage cannot subsequently append a GAP. No production queue is specified here.

## 4. Barriers, deduplication and continuity scope

Each book/stream continuity scope stores invalidation_barrier: RecordNo (0 only as initial frontier sentinel before registration), pending, anchor, warm-up witness/progress and last_applied_raw frontier. Registration sets the new stream's barrier to its StreamDefinition RecordNo. GAP/critical overflow/continuity failure/TransportDown and relevant epoch/spec/config/normalizer changes set barrier to the CURRENT input RecordNo and clear pending, anchor, proofs, warm-up and last-valid sample. Ordinary market silence expires freshness, not the book's continuity by itself.

A new snapshot must have raw_record_no > barrier; exact current owners/tag/config/profile; a verified post-barrier resync basis; and satisfy structural guards. A newly admitted raw with an old receive sample is not automatically a new resync: descriptor sample bounds and the verified profile must establish post-barrier continuity. Generic record ordering alone cannot prove this exchange fact. An Up observation never lowers or clears the barrier.

Evidence disposition order after safe framing/reference resolution:

1. Pre-barrier raw or obsolete tag/config => PRE_BARRIER / OBSOLETE_SCOPE diagnostic. It cannot restore OR invalidate a recovered new generation.
2. For current scope, unresolved artifact => Blocked; scope/commitment conflict => ProofConflict and fail-closed invalidation at this record.
3. Already applied SourceApplicationKey + equivalent proof => ALREADY_APPLIED no-op. No new EventId, anchor, sample or progress. Already proof-ready pending frame + equivalent proof => ALREADY_VERIFIED no-op.
4. Otherwise mark proof-ready and attempt ordered prefix release.

Equivalence compares decision content (scope, raw, barrier, ordered outputs, continuity/basis and temporal bounds), not the later proof's RecordNo or human provenance. Original raw and first accepted proof must resolve from the validated immutable recorded-prefix view; inability to resolve is Blocked, not assumed equivalence. last_applied_raw prevents any older frame being applied again even when it is no longer pending. The reference interface may read an immutable prefix supplied by the caller; this does NOT prescribe an unbounded in-memory production history map. A contradictory current-scope proof fails closed even if its record ID is new. After invalidation, pre-barrier handling takes precedence over historical conflict and cannot poison a new anchor.

Connection generations belong to ConnectionId; subscription to StreamId; book to BookRef. EpochAdvance requires expected=current, next>expected and checked range. Connection changes fan out to all current dependents only; other connections survive. SpecActivate references a previously defined newer spec of the SAME instrument and invalidates its dependents. Owner mismatch is not fixed by equal numeric epochs. CaptureAttemptNo accounting continues across epochs as specified in WAL section 4.1.

## 5. Structural market payloads

BookSnapshot: qualified book/tag, ordered sides/levels, price>0, quantity>0, unique(side,price), bids descending/asks ascending. Empty sides are structurally representable; require_two_sided_snapshot is a separate policy guard.
BookUpdate: ordered SetLevel(side,price>0,qty>0) or DeleteLevel(side,price>0); repeated(side,price) within one update is DuplicateLevel, not last-write-wins. Side Bid=1/Ask=2, not aggressor.
Trade: price>0, quantity>0, unknown-preserving aggressor/RPI/link and optional opaque source trade ID.
Each book output has <=4096 entries. Counts/lengths/arithmetics are checked. Structural success is NOT sequence/resync proof and permits no unverified REST/WS stitching.

## 6. A3/R4: canonical activation timeline

ConfigVersion is defined once. Definition is different from a reference: Config2 may refer to the SAME immutable Norm1 artifact already referenced by Config1. Rebinding (ArchiveId,kind,logical identity,revision) to other bytes is ArtifactIdentityConflict. A valid config3/norm2 then activates a new normalizer on the SAME canonical cursor timeline. Cross-revision references to existing prior effects remain comparable and auditable; they cannot transfer old readiness.

Context belongs to the state before processing a record. ConfigDefinition at r20 uses old config1/norm1, validates the new descriptor and mode/gate, invalidates dependents at barrier20, and installs config2/norm1 for r21. ConfigDefinition at r30 similarly installs config3/norm2 for r31. No ordinary version is zero. The first definition uses a distinct BootstrapContext decoded from wire (0,0), accepted only for administrative InstrumentSpec/StreamDefinition/ConfigDefinition before activation; mixed zero/nonzero and any Bootstrap RawInput/Control/Gap are InvalidBootstrapContext. Bootstrap records have RecordRefs, no EventId with NormalizerVersion=0. Invalid definitions do not activate or partially reset state; semantic processing stops at the failing record.

External availability is separate from activation. Offline discovery of every future descriptor does not enable it before its WAL reference. Config evidence, feed provenance and proof fields bind the exact descriptors and complete dependency closure defined in artifacts-v1. Missing/mismatch/unverifiable => Blocked canonical replay/readiness, no latest/network fallback. Policy change invalidates dependent pending/proofs even when norm version is unchanged. Archive restart remains a new timeline.

## 7. Evaluation and publication boundary

RecordNo is authoritative admission order across raw/control, not a global exchange order. Evaluation time=max(previous maximum, current recorded Context sample, valid TimerFired sample) in one recorded session/clock. A timer must be recorded; reducers do not read wall clock. A decreasing original receive sample neither reverses ordering nor rejuvenates data. Every admissible record can cause scheduled expiry; a duplicate/old-proof diagnostic has no evidence effect, but its valid clock sample can still cause ordinary expiry. IncomparableClock provides no duration/readiness.

Data readiness, immutable publication_candidate and publication_permit are distinct ([health section 5](data-health-v1.md#5-a2-publication-candidate-and-permit)). A candidate derived while processing RecordingEvidence includes that record in its causal prefix. Final StorageFence is a storage operation result, NOT a new WAL/control record, clock tick, market effect or automatic ack-generating cause. Receipt alone never permits publication. Historical state/candidates can replay; physical sync and external delivery cannot be inferred from recorded claims.
