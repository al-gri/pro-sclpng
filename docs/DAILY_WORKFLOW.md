# Ежедневная работа с ProScalping

Открой проект `al-gri/pro-sclpng` в основном чате Codex. Этот чат выполняет роль Integrator; его можно заменить по сохранённой записи GitHub. Для запуска достаточно конкретной задачи или задания «продолжить» ниже. Владелец выбирает результат и принимает решения в своей области; технические передачи организует Integrator.

Короткий путь: [AGENTS](../AGENTS.md) → канонический указатель текущего Issue → актуальный packet/PR. [PROJECT_STATE](PROJECT_STATE.md) даёт карту, [WORKFLOW](WORKFLOW.md) — обязательные правила, [промпт Integrator](prompts/INTEGRATOR.md) — подробное задание. Контракты и историю читать по задаче.

## Что видно владельцу

`READY → IMPLEMENTING → VERIFYING → READY_TO_MERGE → DONE`

При исправлениях возврат в IMPLEMENTING. BLOCKED/PAUSED всегда содержат причину, ответственного и условие продолжения. Полные события SOURCE_FROZEN/QA_ACTIVE и evidence остаются в GitHub; каждая мелкая операция не требует нового документа или ручного переноса между чатами.

| Работа | Как проверяется |
|---|---|
| LOW: только опечатка/несемантическое оформление | Один автор, просмотр diff, подходящая лёгкая проверка и обязательный CI |
| STANDARD: ограниченное изменение поведения | Worker, авторские checks, Integrator и свежий независимый целевой review |
| STRICT: governance/specs/contracts/security, критическое поведение, milestone | Независимый QA и все принятые обязательные gates |

Governance/spec/security/изменения gate не LOW даже в документации. Для текущей #48/PR49 обязательны independent documentary QA и existing CI; #45/M1 gates сохраняются.

## Начать конкретную задачу

```text
Ты — Integrator только al-gri/pro-sclpng. Нужен результат: <результат>.
Текущая задача/PR, если уже есть: <ссылка>.
Сначала сверь GitHub и существующие разрешения. Подготовь один bounded packet,
определи риск, единственного автора и проверки. Выполни уже разрешённые шаги
по WORKFLOW. Для обычной реализации запусти одного Worker и нужный независимый
review/QA; не создавай дубликаты Issue/PR и пользовательские чаты.
Покажи результат, стадию/PR, что доказано, что осталось и одно нужное решение.
```

Если полномочия ещё не заданы, владелец один раз указывает их для конкретной задачи/ограниченной очереди:

```text
Задача/ограниченная очередь: <ID и порядок>.
Разрешаю: <выбрать edit/check/commit/push/Draft PR/report> в указанном scope.
Следующая задача: <только подготовить / выполнить конкретную очередь>.
Остановки и границы: <критерии, спорные решения>.
Merge готового candidate, ADR и milestone — по отдельному owner решению.
```

Незаполненное поле не даёт разрешения; уже выданные разрешения повторять не надо. При изменении требований/контракта Integrator подготовит конкретное решение. Goal для длительного активного выполнения и расписание для возврата позже включаются только по отдельному запросу, не расширяют полномочия. Обычный завершённый ответ не оставляет работающего диспетчера.

## Продолжить или заменить чат Integrator

```text
Восстанови роль Integrator для al-gri/pro-sclpng по каноническому указателю
Issue <ссылка>. Прочитай AGENTS, актуальные packet/PR и нужные правила.
Сверь actual refs, clean/dirty checkout, автора/workspace, freeze, authority,
checks/findings и blockers. Сохрани checkpoint, не повторяй завершённые шаги.
Продолжи ровно следующий разрешённый шаг по WORKFLOW. Если работа paused,
сначала проверь условие возобновления. Не запускай другую delivery задачу.
```

Checkpoint хранит refs, статус/автора, evidence, blockers и следующий шаг. Для смены роли Integrator сохраняет полный уникальный versioned packet в GitHub и запускает subagent. Если spawn недоступен, отдаёт один готовый prompt с честным ограничением. Создание отдельного пользовательского чата и сообщения другим чатам требуют явной пользовательской авторизации.

## Обсудить архитектуру

```text
Ты — Architect только al-gri/pro-sclpng. Разбери вопрос: <вопрос/Issue>.
Прочитай актуальный scope, accepted contracts/ADR и затронутые invariants.
Если это продолжение, восстанови последнее авторизованное решение и открытые
вопросы по canonical Issue/packet; не повторяй уже принятое обсуждение.
Дай варианты, ограничения, рекомендуемый контракт, проверяемые критерии,
открытые вопросы и точное требуемое owner решение. Сохрани proposed/accepted
границу: обсуждение не принимает ADR и не разрешает зависимую реализацию.
Верни короткий результат для canonical Issue/packet Integrator; всю историю
чата переносить не нужно. Не меняй runtime и не запускай feature delivery.
```

Для Architect можно использовать уже выбранный чат обсуждения; открывать новый автоматически не требуется. Результат обсуждения становится authority только после необходимого принятия и записи в GitHub.
