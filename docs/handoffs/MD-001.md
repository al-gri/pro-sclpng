## Main proven Bitget facts

- Regular production public WS: wss://ws.bitget.com/v3/ws/public.
- Demo public WS: wss://wspap.bitget.com/v3/ws/public; Demo docs require a Demo API Key.
- Regular books50/publicTrade categories: spot, usdt-futures, coin-futures, usdc-futures.
- books50: first push snapshot, subsequent incremental updates, 20 ms, asks ascending, bids descending.
- books50 continuity: previous update seq must equal next update pseq; snapshot seq lies in the first update [pseq,seq] interval.
- Sequence reset is documented around release/restart; pseq=0 is described only as “most likely”, not exhaustive.
- publicTrade exposes p/v/i/L/S/T/isRPI; JSON documentation labels S only “Fill side”.
- Trade size unit: COIN-FUTURES quote coin; the other documented categories base coin.
- Heartbeat: client ping every 30 s, server pong; server disconnects after two minutes without ping.
- Limits: 300 connection requests/IP/5 min, max 100 connections/IP, 240 subscription requests/hour/connection, max 1000 channel subscriptions/connection, max 10 client messages/s/connection.
- REST order book has timestamp but no seq/pseq; no common REST↔WS sequence bridge is documented.
- RPI books are separate; standard and RPI sequence rules are independent; rpi-books50 is snapshot every push at 100 ms and carries [price, non-RPI qty, RPI qty].
- books50 is a price-level aggregate/MBP view with no individual order IDs/FIFO/participant identity.
- BG-BEST documents final-state coalescing for multiple depth changes within a short period (including A→B→A); intermediate book states/events are not guaranteed observable.
- Instrument-path documentation conflicts: dedicated BG-MARKET and 2026-09-20 BG-CHANGE use /api/v3/market/instruments, while BG-BEST/BG-UPGRADE use /api/v3/public/instruments. MD-001 references /market/instruments by stated precedence; the /public relationship remains unknown.
