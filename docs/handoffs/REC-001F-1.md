Seven accepted synthetic Bitget JSON sources are embedded byte-for-byte, including decimal/zero lexemes. Initial Windows CRLF checkout representation was restored to exact Git blob bytes before building, and all source hashes match the accepted manifest. No accepted source blob was changed.

Golden diagnostic report: **52054 bytes**, fixed LF output. Two fresh processes match each other and the committed golden. The versioned report explicitly serializes recorded context/control/GAP/structural data, decoded lexical inputs and accepted reducer snapshots/effects using the pinned Rust DTO Debug representation. Recorded input order is always RecordNo order. Identity-indexed snapshots inherit accepted BTree ordering. No current time, PID, absolute input path, duration, random value or dynamic capacity enters the report.

Every reader-accepted record inside the supported semantic prefix receives exactly one reducer step. ArchiveStart uses empty-scope sample 0; context-bearing records use their recorded monotonic sample; seals repeat the last recorded sample. Structural records are Noop; stream definitions RegisterStream; Transport/Epoch/GAP/book/Timer map to existing observations. Book candidate cardinality is exactly one per supported homogeneous frame, independent of level count. Category/symbol/topic is checked before BookFrame. No partial frame succeeds.

RecordingEvidence has no observation variant in the accepted reducer: its dense step is documented Noop, while the application separately preserves observed kind/through/health and terminal Failed latch. Later Healthy cannot clear Failed. It is never a trusted StorageFence or historical sync/publication/delivery receipt.

Later ConfigDefinition, SpecActivate, Verification, Warmup and Freshness controls stop dependent projection before that record, return nonzero, and identify blocking RecordNo/reason. The bounded physical reader can continue separately; suffix records are explicitly NotApplied. The reader is called through actual EOF after ArchiveSeal. Physical failure follows its existing typed classification without skip/scan/rejoin/repair.

Every report preserves `canonical_status=NotEvaluated`, `canonical_applicability=BLOCKED_UNVERIFIED`, and `usable_data=false`.
