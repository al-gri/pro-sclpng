## 4. in_scope / минимальная composition

1. Один сериализованный owner/turn; одна synthetic books50 scope, один connection/book. Записать небольшой неизменный synthetic bootstrap/profile через `CaptureSessionOwner::create_new`; выбрать Durable gate и совместимый archive mode. Фиксированные session/archive/clock IDs и инженерные metadata маркировать synthetic/unverified. `create_new` не перезаписывает существующий output.
2. `register_supervisor(turn, scopes, budget, HeartbeatPolicy::SupervisorV2)` → настоящий handle + `BoundRecordSink`; `PublicWsSupervisor::new(config, handle)` с точно совпадающими bindings/prefix/gate/budget. При необходимости shutdown сохранить только разрешённый authority clone перед передачей handle.
3. `start_commands`, `queue_connected`, `queue_text`, `queue_disconnected`, `queue_tick` со scripted оригинальными stamps; затем существующий `drain_one`. Fake transport фиксирует/исполняет только полученные команды через `owner.dispatch(turn, lease, synchronous_effect)`; наблюдения script подаются отдельными явными inputs, без callback reentrancy.
4. Проверять не только `outcome`, но и outer `session_disposition`, typed errors, `close_owner`, events/leases каждого admission/drain report. Не терять обязательный Close при ошибке. Каждый результат/lease — counted owner; не держать ненужные aliases после обработки.
5. Script clock выбирает наблюдаемые stamps; scheduler/Timer IDs/kind/deadline/generation выбирает существующая authority. Не создавать app scheduler/FSM. `SupervisorV2` revision2: Ping 30_000_000_000 ns, Pong timeout 15_000_000_000 ns. Это engineering preset, не гарантия Bitget/freshness. Wire heartbeat — text `ping` и received `pong`, не RFC WS control frames.
6. Shutdown: закрыть admission через `begin_finalization`; дренировать ранее admitted work, обслужить настоящий mandatory Close, освободить counted результаты/leases, получить `supervisor.quiesce(..., ticket)` и единственный consumable proof; `owner.finalize` пишет seals. Не выдумывать received Disconnected для локального stop. При failed/storage-stopped архиве — `close_diagnostic` и честный report, без retry записей/seals.
7. Mandatory Close обнаруживать через outer report или `owner.outstanding_close_owners`, выполнять owner-bound dispatch/reclaim той же opaque identity. Для локального stop без существующего Down/Timeout запросить Close через уже публичный `authority.mandatory_close(turn, stream, current_epoch, None)` той же owner-issued authority (сохранённой из handle либо доступной через `sink.authority()`), затем reclaim/dispatch. При существующем Timeout использовать его оригинальный Close и соблюдать CloseNotReady; не создавать вторую authority/Close identity или received observation. Не конструировать `AuthenticatedClosure`: публичного producer нет. Успех fake callback — лишь принятый synthetic effect, не peer acknowledgement.
8. Читать реально созданный, закрытый файл существующим `WalReader` до результата/EOF; отдельно выводить runtime lifecycle/failed/storage stop, trusted watermarks, physical recovery/optional input_quality, loss/undrained/Close status и ограничения данных.

Driver хранит bounded scripted inputs/effect diagnostics: зафиксировать явные пределы (не более 64 observations и 64 effect entries, payload не более 4096 bytes, максимум 64 KiB суммарных scripted raw bytes) с checked arithmetic и явной ошибкой. Drain/quiescence/reclaim loops имеют явный конечный ceiling не более 256 шагов и 2 effect attempts на одну Close identity; NotReady требует конкретного progress либо явного bounded refusal, а не бесконечного poll. Это ceilings demo, не новые library/exchange thresholds. Для overflow намеренно выбрать меньший согласованный library budget. Проверить ограничения перед началом script. Reader scan streaming, без unbounded полного архива в RAM. Не заявлять RSS/latency/performance по metadata bounds. Стабильный diagnostic stdout — JSON с фиксированными полями; он не включает OS error strings, path-dependent allocation sizes или произвольные Debug dumps; environment детали остаются в отдельных evidence logs.

Capture profile **отдельный** от F-1: supervisor требует venue `bitget` в нижнем регистре; accepted F-1 использует `Bitget` и не поддерживает RawInput subscription ACK. F-2 должен законно пройти ACK перед books snapshot; чтение его WAL выполняет WalReader. Не обещать успешный полный `radar-replay` этого архива и не менять F-1 ради совместимости.

## 6. Acceptance criteria

**AC1 — номинальная запись.** Fake Connect dispatch, received Connected, genuine SendText subscribe dispatch, received exact subscription ACK, несколько отличимых books raw с non-sorted exchange timestamps. WalReader подтверждает исходные байты/stamps и dense RecordNo/receive order; только existing contracted controls. Синтетическая session действительно проходит filesystem owner/bound sink, не writer-built substitute.

**AC2 — Timer A.** Positive Ping/Pong и timeout/Close; D−1/D/D+1, duplicate tick, Pong-first vs Timeout-first admission order. Delayed drain/effect не сдвигает original Timer+15s/Connected-or-Pong+30s. Timeout пишет Timer→Down, одна оригинальная mandatory Close; Timer-only не разрешает Close. Held Ping после Pong/Closing/timeout revocation не вызывает callback. Ping effect error — AmbiguousEffect::Unknown, без Ping retry. App тесты проверяют wiring/effect counts/записанный WAL, не дублируют library FSM.

**AC3 — отрицательные пути.** Scripted SendText/Ping transport failure и received Disconnected имеют честное различие: ошибка dispatch сама по себе не обязана failed-latch archive. Callback attempt сохраняется; ambiguous effect не теряется. Close error/Drop оставляет тот же Pending owner; lawful reclaim, повторный успех и settlement не создают второго Close owner/lease. После ambiguous retry не заявлять exactly-once physical Close. Переполнение bounded queue/raw bytes и oversized message возвращают existing typed result и trusted prefix, без скрытой потери. Различать representable raw-frame/byte/message loss (CoalescedLoss и truthful GAP, без обязательного archive Failed/Close) и terminal item/work QueueExhausted (failed/marker/Close по действующим контрактам). CLI overflow демонстрирует terminal cap exhaustion; отдельные app tests проверяют coalesced loss. Не требовать одинаковых Failed/marker/Close для всех overflow исходов.

**AC4 — запись/завершение.** Public `owner.set_sink_fault` с `SinkFaultKind::BeforeWrite(PersistError)` на точном будущем RecordNo — допустимая negative-only инъекция existing sink, не настоящая OS disk fault. Дренирование вызывает её через BoundRecordSink; storage stopped, no write retry/final seals, diagnostic prefix/unknown quality. Не требовать first_failure=Some: storage stop может быть отдельным latch.

Здоровый shutdown: pending result/lease/Close сначала даёт NotReady; после законного drain/settlement/release — Ready, finalize один раз, unique final SegmentSeal/ArchiveSeal, actual EOF, physical Complete, owner quality Unknown; повторная финализация/новые effects не проходят. Отказ завершения: Open admission Raw после успешного ACK, затем begin_finalization, инъекция BeforeWrite на этом уже admitted Raw и его drain в Closing; failed/storage stopped, FinalizationInvalidated, diagnostic close, WalReader incomplete/no seals/quality None. Не выдумывать публичную инъекцию seal-write failure; unresolved owners могут остаться и должны попасть в report.

**AC5 — повторяемость.** Два отдельных процесса example с теми же inputs/profile/stamps и разными fresh UTF-8 output paths: побайтово одинаковые WAL и stdout. В canonical stdout исключить пути/PID/live clock/durations/randomness; эти сведения оставить evidence manifest. Повторить все failure scripts на app тестах с одинаковыми нормализованными outcomes. Existing output file, неверные CLI args/unknown scenario, script bounds дают nonzero без overwrite/panic.

**AC6 — corruption/tail.** После настоящего owner capture тесты создают отдельные копии файла: middle CRC corruption, torn payload/header, удалённый whole ArchiveSeal и хвост после ArchiveSeal. Existing WalReader даёт точный тип/status и последний good physical prefix по WAL v1; ни один негатив не Complete, никакого magic scan/skip/rejoin/repair. Отличать absent seals/optional quality от runtime Unknown. Исходный файл не мутировать; tests лишь повреждают отдельные copies, WAL код не переписывают.

**AC7 — demo, regression, quality.** CLI interface:

```text
capture_scripted --scenario nominal|heartbeat-pong|heartbeat-timeout|transport-error|overflow|write-error|shutdown-refused --output <fresh-path.wal>
```

Nominal/здоровые diagnostic сценарии exit0 допускается лишь при выполнении их lifecycle assertions; это не data usability. `transport-error`, `overflow`, `write-error`, `shutdown-refused` — nonzero с bounded deterministic diagnostic stdout и явным typed error/status. Direct successful nominal stderr пуст. Приватные tests могут иметь дополнительные interleavings. Зафиксировать actual exit codes в DEVELOPMENT/Handoff. Existing radar/F-1 fixtures/profile/commands и tests сохраняются. All workspace debug gates, focused F-2 debug/release и существующие Timer/finalization/F-1 regressions проходят на final exact head. Independent QA — отдельный следующий чат, не self-approval worker.
