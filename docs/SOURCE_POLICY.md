# Источники и ограничения публикации

## Что сохранено сейчас

Bootstrap содержит инженерную организацию и сжатый baseline из проектной переписки. Полные транскрипции, прежние MD/JSON/YAML/CSV и аудит из чатов в этот repo НЕ импортированы. Их точное количество и актуальность здесь не проверены.

Политика публичного repo: не загружать полный платный курс или приватные чаты. Разрешённость публикации производных материалов проверяет владелец. Возможные варианты — закрытое хранилище с source manifest либо только минимальные согласованные формулировки правил. Наличие файла в прошлой беседе не доказывает, что новый worker имеет доступ к его содержимому.

## Типы происхождения

- AUTHOR_EXPLICIT: найден точный источник и контекст.
- AUTHOR_QUALITATIVE: подтверждена формулировка, числовой threshold не задан.
- ENGINEERING_POLICY: наше решение по системе, не цитата автора.
- ENGINEERING_CALIBRATION: тестируемый параметр.
- EXCHANGE_SPEC: официальный API, дата/версия проверки.
- RESEARCH_HYPOTHESIS: не доказано.
- SOURCE_MISSING / UNVERIFIED: пока не подтверждено.

Число строк прежней матрицы не равно числу независимых правил. Aliases не увеличивают score. Частные примеры не становятся универсальными порогами.

## Исторические утверждения, которые не приняты как mandatory baseline

Обязательные Tokyo/AWS, DPDK/AF_XDP, SBE, Hawkes/PCA, гарантии <2ms, автоматическая идентификация айсберга/участника, обязательная CPCV до любого кода. Их нельзя внедрять только потому, что они есть в старом аудите.

Это явный отказ от некоторых прежних предложений на уровне инженерной политики, а не исправление текста автора курса. API-факты проверяет MD-001. Торговые правила проверяет RULE-001. Позднее утверждённое ADR имеет приоритет над старым неутверждённым обсуждением.

## Manifest источника

Для каждого разрешённого материала: source_id, title, private/public, content hash, версия, location, доступный диапазон/таймкод, review status. Не включать секретную ссылку с токеном. Без источника правило не объявляется verified.
